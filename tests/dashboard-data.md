# Погода й повітряні тривоги

FEAT-010: історію відключено від прошивки; наведений нижче legacy history suite перевіряє лише збережений вихідний модуль. Екрану деталей немає, `active.json` використовується для короткого статусу та територіальних значків типів загроз. Details suite додатково перевіряє агрегацію типів по Україні (обласні/дочірні UID, дублікати, невідомі типи, завершені тривоги, очищення порожнім знімком і окремий Київ).

Модель масштабування:

```powershell
cl /nologo /std:c11 /utf-8 /W4 /I main tests/dashboard_map_view_test.c main/dashboard_map_view.c /Fo:build/ /Fe:build/dashboard_map_view_test.exe
.\build\dashboard_map_view_test.exe
```

Перевіряються fixed fit480×327, фактичні непорожні bounds RLE без втрати географії, source/project roundtrip кожного пікселя, мітка Дніпра та безпечне читання canvas480×480. Category mask→шість різних піктограм без дублікатів, габарити груп і bounds векторних assets24×24.

| Сценарій | Очікуваний результат |
| --- | --- |
| Open-Meteo повертає валідне числове `current.temperature_2m` та °C. | На екрані з’являється температура Дніпра й вік останнього успішного оновлення. |
| Значення температури від’ємне, дорівнює нулю або має десяткову частину. | Знак і десяткова кома відображаються правильно. |
| Пошкоджений JSON, відсутня температура або інші одиниці. | Нова відповідь відхиляється. Попередній показник позначається застарілим. |
| Alerts.in.ua повертає 27 кодів `R/Y/P/N`. | Коди накладаються на регіони в порядку джерела. Часткова тривога в області не подається як підтверджена тривога в місті. |
| Відповідь має невідому літеру, неправильну довжину або HTTP 401/429. | Стан не змінюється на «Тривог не повідомлено». Після 401 відображається стан токена, після 429 запити сповільнюються. |
| Токена немає. | Карта залишається нейтральною й має позначку «Потрібен токен». Погода продовжує оновлюватися. |
| Зникає Wi‑Fi чи відповідь джерела прострочена. | Екран продовжує реагувати на дотик. Останні дані позначаються застарілими. |
| Живі джерела увімкнено. | Погода й тривоги продовжують оновлюватись незалежно від доступу до графіка ЦЕК 5.2. |

Збірка: `idf.py build` в активованому терміналі ESP-IDF. На платі перевірити запити з підключеною мережею, тимчасовий розрив Wi‑Fi та повторне оновлення після відновлення.

## Автоматична перевірка парсерів на Windows

У Developer PowerShell для Visual Studio перейдіть до `build` після збірки прошивки та виконайте:

```powershell
cl /nologo /std:c11 /utf-8 /W3 /I"..\main" /I"..\managed_components\espressif__cjson\cJSON" "..\tests\dashboard_data_parse_test.c" "..\main\dashboard_data_parse.c" "..\main\dashboard_energy_parse.c" "..\managed_components\espressif__cjson\cJSON\cJSON.c" /Fe:dashboard_data_parse_test.exe
.\dashboard_data_parse_test.exe
```

## Деталі тривог

У корені проєкту, в Developer PowerShell:

```powershell
cl /nologo /std:c11 /utf-8 /W4 /D_CRT_SECURE_NO_WARNINGS /I main /I managed_components/espressif__cjson/cJSON tests/dashboard_alert_details_test.c main/dashboard_alert_details.c managed_components/espressif__cjson/cJSON/cJSON.c /Fo:build/ /Fe:build/dashboard_alert_details_test.exe
.\build\dashboard_alert_details_test.exe
```

Перевіряються обласні й локальні записи UID 9, фільтрування інших областей і завершених записів, відсутні optional поля, невідомі загрози, збереження попереднього знімка при невалідному JSON, межі записів/загроз/тіла відповіді, UTF-8, UTC і київські переходи доби/DST. HTTP-кеш: 304 без кешу, 200→304 та незалежність endpoint; ліміт: ковзні 60 с, 401 і короткий/довгий Retry-After. Перевірка відповідності деталей поколінню місцевого стану не дозволяє видавати старі деталі за нову тривогу.

На пристрої окремо перевірити 200→304 для обох endpoint, збій тільки деталей, завелику відповідь, втрату/відновлення Wi-Fi й збереження опитування погоди та ЦЕК. Журнал деталей містить лише HTTP-код, результат валідації й розмір тіла, без ключа чи тексту відповіді.

## Історія тривог

```powershell
cl /nologo /std:c11 /utf-8 /W4 /D_CRT_SECURE_NO_WARNINGS /I main /I managed_components/espressif__cjson/cJSON tests/dashboard_alert_history_test.c main/dashboard_alert_history.c main/dashboard_alert_details.c managed_components/espressif__cjson/cJSON/cJSON.c /Fo:build/ /Fe:build/dashboard_alert_history_test.exe
.\build\dashboard_alert_history_test.exe
```

Покриття: десять найновіших із перемішаного списку, дублікати, фільтри області/типу, порожня/пошкоджена/завелика відповідь, атомарне збереження попереднього знімка. Перевіряються null/відсутній відбій, негативна/майбутня тривалість, перехід дати/року/DST, TTL15хв, повторні відкриття, offline/pending, 304 без кешу й 200→304, бюджет історії 2/60 с у межах спільних 6/60 с та відсутність автоматичного повтору після збою.

Додаткові live-регресії: 9000 записів у відповіді1843902байти (понад фактично виміряні1,74МБ), numeric/string UID, явна назва потрібної області з іншим UID та відсікання явної іншої області навіть при legacyUID9.


## Вибір міста (FEAT-016)

У Developer Command Prompt із доступним `cl`:

```powershell
C:/Espressif/tools/python/v6.1/venv/Scripts/python.exe tests/test_dashboard_recovery_source.py
C:/Espressif/tools/python/v6.1/venv/Scripts/python.exe tests/test_dashboard_workers.py
```

Перший runner також компілює `dashboard_location_test.c` із fake NVS: усі 463 стабільні ID, координати/межі проєкції, 27 територій, однакові назви різних областей, Київ/область і Севастополь/Крим, URL, перший старт, збереження/відновлення та помилки open/write/commit. Real-worker fixture перевіряє відповіді після A→B і A→B→A, старі active.json 200/304, відсутність умовного заголовка для іншого міста, незмінність застосованого вибору при NVS-помилці й збереження error backoff. Parser suite перевіряє вибір локальних записів п’яти територій без зміни загальних masks.

Concurrent runner містить попередні 16 сценаріїв та 4 нові: перемикання після завершеного запиту (наступне опитування через 600 с), під час заблокованого weather HTTPS, A→B→A під час HTTPS і перемикання offline з відновленням мережі. Перевіряє нове покоління, очищення старої температури, швидке оновлення без reset задач і незмінність чинного графіка енергії.

Регресія пам’яті списку: runner компілює справжні callbacks списку міст проти UI doubles, які виділяють об’єкти, та справжнього каталогу. Перевіряє максимум 8 кнопок + елемент висоти прокрутки, усі області й позиції прокрутки, точну прив’язку міста та вибір після повторного використання рядка. До виправлення eager-список падав на childcount<=9. Це перевірка кількості об’єктів і callback-логіки; фактичні витрати LVGL/TLS перевіряються на платі.
